description: "Inspect which API key would be used at session creation time, and manage keys for additional agent providers (Cursor, Devin, Gemini, Copilot)."
---

When a session boots, Runtime picks the right credential for the chosen agent
in this order:

1. **Org enforced shared key** - when the organization has a key configured
   and `policy="enforced"`.
2. **User's org-scoped personal key** - when the caller has saved a key
   against the current organization.
3. **User's pure-personal key** - the caller's account-wide key.
4. **None** - the session prompts for a key (or fails if the agent does not
   support prompting).

This page covers two surfaces:

- The **resolved** endpoints for Anthropic and OpenAI, which return what the
  resolution above would produce without exposing the actual key value.
- The **generic provider key** endpoints used for the additional agents
  (Cursor, Devin, Gemini, Copilot), which support the same personal/org +
  resolution model.

<Note>
  All endpoints on this page only return masked previews and metadata - 
  values are never returned.
</Note>

## Anthropic resolved key

### GET /api/user/anthropic-key/resolved

<Info>
  Required scope: `integrations:read`
</Info>

Returns the Anthropic key that would be used to start a session right now,
without exposing the key value.

#### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <your_api_key>`
</ParamField>

<ParamField header="X-Organization-Id" type="string">
  Optional. Includes org-shared and user-scoped-org keys in the resolution.
</ParamField>

#### Response

<ResponseField name="has_key" type="boolean">
  `true` when a key would be available; `false` when the session would
  prompt.
</ResponseField>

<ResponseField name="source" type="string">
  Where the resolved key came from. One of `"org"` (enforced shared key),
  `"user_org"` (caller's key for this org), `"user"` (caller's pure-personal
  key), or `"none"` when `has_key` is `false`.
</ResponseField>

<ResponseField name="key_preview" type="string">
  Masked preview of the resolved key, or `null`.
</ResponseField>

<RequestExample>
```bash cURL
curl -X GET "https://app.runtm.com/api/user/anthropic-key/resolved" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "X-Organization-Id: org_abc123"
```

```python Python
import requests

response = requests.get(
    "https://app.runtm.com/api/user/anthropic-key/resolved",
    headers={
        "Authorization": "Bearer runtm_xxx",
        "X-Organization-Id": "org_abc123",
    },
)
print(response.json())
```

```javascript JavaScript
const response = await fetch(
  "https://app.runtm.com/api/user/anthropic-key/resolved",
  {
    headers: {
      Authorization: "Bearer runtm_xxx",
      "X-Organization-Id": "org_abc123",
    },
  },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200 (org-enforced)
{
  "has_key": true,
  "source": "org",
  "key_preview": "sk-ant-***WxYz"
}
```

```json 200 (user fallback)
{
  "has_key": true,
  "source": "user",
  "key_preview": "sk-ant-***mnop"
}
```

```json 200 (no key)
{
  "has_key": false,
  "source": "none",
  "key_preview": null
}
```
</ResponseExample>

## Generic provider keys

For agents other than Anthropic and OpenAI, the API exposes a single set of
endpoints parameterised by `provider`. The supported providers are:

| Provider slug | Used by agent |
|---------------|---------------|
| `cursor` | Cursor CLI |
| `devin` | Devin CLI |
| `gemini` | Gemini CLI |
| `copilot` | GitHub Copilot CLI |

The personal/org behavior, policy semantics, and `enforced` requirements
match the Anthropic and OpenAI endpoints on the dedicated pages.

<Note>
  Values are never returned. Responses include only a masked preview, a
  `connected` / `has_key` flag, and the active policy (for org keys).
</Note>

### GET /api/user/provider-keys/{provider}

<Info>
  Required scope: `integrations:read`
</Info>

Read the caller's stored personal provider key for the current context.

#### Path Parameters

<ParamField path="provider" type="string" required>
  One of `cursor`, `devin`, `gemini`, `copilot`.
</ParamField>

#### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <your_api_key>`
</ParamField>

<ParamField header="X-Organization-Id" type="string">
  Optional.
</ParamField>

#### Response

<ResponseField name="provider" type="string">
  Echo of the path `provider`.
</ResponseField>

<ResponseField name="connected" type="boolean">
  `true` if the caller has a personal key for this provider.
</ResponseField>

<ResponseField name="key_preview" type="string">
  Masked preview, or `null`.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the last update, or `null`.
</ResponseField>

<RequestExample>
```bash cURL (read)
curl -X GET "https://app.runtm.com/api/user/provider-keys/cursor" \
  -H "Authorization: Bearer runtm_xxx"
```

```python Python (read)
    "https://app.runtm.com/api/user/provider-keys/cursor",
    headers={"Authorization": "Bearer runtm_xxx"},
)
print(response.json())
```

```javascript JavaScript (read)
const response = await fetch(
  "https://app.runtm.com/api/user/provider-keys/cursor",
  { headers: { Authorization: "Bearer runtm_xxx" } },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200 (connected)

  "key_preview": "***WxYz",
```

```json 200 (not connected)
  "updated_at": null
```

</ResponseExample>

### Organization provider keys

<Warning>
  Setting and deleting an organization provider key requires the caller to
  be an org **owner** or **admin**.
</Warning>

<Note>
  Organization context is required. Set `X-Organization-Id` to match the
  path `org_id`, or use an org-scoped API key whose org ID matches.
</Note>

#### GET /api/organizations/{org_id}/provider-keys/{provider}

<Info>
  Required scope: `integrations:read`
</Info>

Read the org's stored provider key (status only) and the active policy.

##### Path Parameters

<ParamField path="org_id" type="string" required>
  Organization ID. Must match `X-Organization-Id` (or the API key's org).
</ParamField>

<ParamField path="provider" type="string" required>
  One of `cursor`, `devin`, `gemini`, `copilot`.
</ParamField>

##### Response

<ResponseField name="organization_id" type="string">
  Echo of the path `org_id`.
</ResponseField>

<ResponseField name="provider" type="string">
  Echo of the path `provider`.
</ResponseField>

<ResponseField name="has_key" type="boolean">
  `true` when the org has a stored key for this provider.
</ResponseField>

<ResponseField name="key_preview" type="string">
  Masked preview, or `null`.
</ResponseField>

<ResponseField name="policy" type="string">
  `"individual"` (default) or `"enforced"`.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the last update, or `null`.
</ResponseField>

#### PUT /api/organizations/{org_id}/provider-keys/{provider}

<Info>
  Required scope: `integrations:write`
</Info>

<Warning>
  Org owner or admin role required.
</Warning>

Set the org provider key, the active policy, or both. Setting
`policy="enforced"` requires the org to have a stored key (either supplied in
the same call or already present).

##### Path Parameters

<ParamField path="org_id" type="string" required>
  Organization ID.
</ParamField>

<ParamField path="provider" type="string" required>
  One of `cursor`, `devin`, `gemini`, `copilot`.
</ParamField>

##### Request Body

<ParamField body="api_key" type="string">
  Provider API key (minimum 8 characters when provided). Required when
  switching to `policy="enforced"` for the first time.
</ParamField>

<ParamField body="policy" type="string">
  `"individual"` (default) or `"enforced"`.
</ParamField>

##### Response

Same shape as the GET response, reflecting the updated state.

<RequestExample>
```bash cURL (set org key)
curl -X PUT "https://app.runtm.com/api/organizations/org_abc123/provider-keys/cursor" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "X-Organization-Id: org_abc123" \
  -H "Content-Type: application/json" \
  -d '{"api_key": "...", "policy": "enforced"}'
```

```python Python (set org key)
import requests

response = requests.put(
    "https://app.runtm.com/api/organizations/org_abc123/provider-keys/cursor",
    headers={
        "Authorization": "Bearer runtm_xxx",
        "X-Organization-Id": "org_abc123",
    },
    json={"api_key": "...", "policy": "enforced"},
)
print(response.json())
```

```javascript JavaScript (set org key)
const response = await fetch(
  "https://app.runtm.com/api/organizations/org_abc123/provider-keys/cursor",
  {
    method: "PUT",
    headers: {
      Authorization: "Bearer runtm_xxx",
      "X-Organization-Id": "org_abc123",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ api_key: "...", policy: "enforced" }),
  },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200
{
  "organization_id": "org_abc123",
  "provider": "cursor",
  "has_key": true,
  "key_preview": "***WxYz",
  "policy": "enforced",
  "updated_at": "2026-05-09T22:14:00Z"
}
```

```json 400
{
  "detail": "An API key is required when setting policy='enforced'."
}
```
</ResponseExample>

<Info>
  Required scope: `integrations:write`
</Info>

<Warning>

</Warning>

Remove the org provider key and reset the policy to `"individual"`.

##### Path Parameters

<ParamField path="org_id" type="string" required>
  Organization ID.
</ParamField>

<ParamField path="provider" type="string" required>
  One of `cursor`, `devin`, `gemini`, `copilot`.
</ParamField>

##### Response

Same shape as the GET response, with `has_key: false`, `key_preview: null`,
and `policy: "individual"`.
