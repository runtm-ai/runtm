---
title: "Anthropic API Keys"
api: "/api/user/anthropic-key, /api/organizations/{org_id}/anthropic-key"
description: "Manage personal and organization-shared Anthropic API keys used by Claude-powered sessions. Values are never returned by any endpoint."
---

Sessions that run Anthropic-backed agents need an Anthropic API key. Runtime
stores the key on the caller's behalf so sessions can boot without a per-run
prompt. Two scopes are available:

- **Personal Anthropic keys** - saved under the caller's account and used by
  default. Scoped per `(user, organization)` so you can separate keys across
  contexts.
- **Organization Anthropic keys** - set by org owners/admins and shared with
  every member. Two policies control how they interact with personal keys:
  - `individual`: every member uses their own personal key. The org key, if
    set, is ignored.
  - `enforced`: the org key is used first; per-member personal keys are only
    used as fallbacks if no org key is configured.

To inspect which key would be used at session creation time, use
[Resolved Provider Keys](/cloud-api/configuration/provider-keys-resolved).

<Note>
  Values are never returned by any endpoint on this page. Responses include
  only a masked preview (`sk-ant-***...XXXX`) and a "connected" / "has_key"
  flag. Treat keys as opaque, write-only values once stored.
</Note>

## Personal Key

### GET /api/user/anthropic-key

<Info>
  Required scope: `integrations:read`
</Info>

Read the caller's stored personal Anthropic key for the current context.

#### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <your_api_key>`
</ParamField>

<ParamField header="X-Organization-Id" type="string">
  Optional. Reads the personal key scoped to the given organization.
</ParamField>

#### Response

<ResponseField name="connected" type="boolean">
  `true` if a personal key is configured.
</ResponseField>

<ResponseField name="key_preview" type="string">
  Masked preview of the stored key (e.g. `sk-ant-***xxxx`), or `null` when
  none is set.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the last update, or `null` when never set.
</ResponseField>

<RequestExample>
```bash cURL (read)
curl -X GET "https://app.runtm.com/api/cloud/user/anthropic-key" \
  -H "Authorization: Bearer runtm_xxx"
```

```python Python (read)
import requests

response = requests.get(
    "https://app.runtm.com/api/cloud/user/anthropic-key",
    headers={"Authorization": "Bearer runtm_xxx"},
)
print(response.json())
```

```javascript JavaScript (read)
const response = await fetch(
  "https://app.runtm.com/api/cloud/user/anthropic-key",
  { headers: { Authorization: "Bearer runtm_xxx" } },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200 (connected)
{
  "connected": true,
  "key_preview": "sk-ant-***WxYz",
  "updated_at": "2026-04-12T18:30:11Z"
}
```

```json 200 (not connected)
{
  "connected": false,
  "key_preview": null,
  "updated_at": null
}
```
</ResponseExample>

### PUT /api/user/anthropic-key

<Info>
  Required scope: `integrations:write`
</Info>

Save a personal Anthropic API key. The key is encrypted at rest and never
returned by any endpoint after this point.

#### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <your_api_key>`
</ParamField>

<ParamField header="X-Organization-Id" type="string">
  Optional. Stores the personal key against the given organization.
</ParamField>

#### Request Body

<ParamField body="api_key" type="string" required>
  Anthropic API key. Must start with `sk-ant-` or `sk-`. Minimum 10
  characters.
</ParamField>

#### Response

Same shape as `GET /api/user/anthropic-key`, with `connected: true`.

<RequestExample>
```bash cURL (write)
curl -X PUT "https://app.runtm.com/api/cloud/user/anthropic-key" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "Content-Type: application/json" \
  -d '{"api_key": "sk-ant-..."}'
```

```python Python (write)
import requests

response = requests.put(
    "https://app.runtm.com/api/cloud/user/anthropic-key",
    headers={"Authorization": "Bearer runtm_xxx"},
    json={"api_key": "sk-ant-..."},
)
print(response.json())
```

```javascript JavaScript (write)
const response = await fetch(
  "https://app.runtm.com/api/cloud/user/anthropic-key",
  {
    method: "PUT",
    headers: {
      Authorization: "Bearer runtm_xxx",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ api_key: "sk-ant-..." }),
  },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200
{
  "connected": true,
  "key_preview": "sk-ant-***WxYz",
  "updated_at": "2026-05-09T22:14:00Z"
}
```

```json 400
{
  "detail": "Invalid API key format. Key should start with 'sk-ant-' or 'sk-'"
}
```
</ResponseExample>

### DELETE /api/user/anthropic-key

<Info>
  Required scope: `integrations:write`
</Info>

Remove the caller's stored personal Anthropic key for the current context.
Subsequent sessions will prompt for a key (or fall back to the org key if
configured).

#### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <your_api_key>`
</ParamField>

<ParamField header="X-Organization-Id" type="string">
  Optional. Removes the personal key scoped to the given organization.
</ParamField>

#### Response

Same shape as `GET /api/user/anthropic-key`, always with
`connected: false`.

<RequestExample>
```bash cURL (delete)
curl -X DELETE "https://app.runtm.com/api/cloud/user/anthropic-key" \
  -H "Authorization: Bearer runtm_xxx"
```

```python Python (delete)
import requests

response = requests.delete(
    "https://app.runtm.com/api/cloud/user/anthropic-key",
    headers={"Authorization": "Bearer runtm_xxx"},
)
print(response.json())
```

```javascript JavaScript (delete)
const response = await fetch(
  "https://app.runtm.com/api/cloud/user/anthropic-key",
  {
    method: "DELETE",
    headers: { Authorization: "Bearer runtm_xxx" },
  },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200
{
  "connected": false,
  "key_preview": null,

```
</ResponseExample>

## Organization Key

<Warning>
  Setting and deleting the organization Anthropic key requires the caller to
  be an org **owner** or **admin**. Members with `integrations:write` on
  their key will still receive `403`.
</Warning>

<Note>
  Organization context is required for all org-key endpoints. Set
  `X-Organization-Id` to match the path `org_id`, or use an org-scoped API
  key whose org ID matches.
</Note>

### GET /api/organizations/{org_id}/anthropic-key

<Info>
  Required scope: `integrations:read`
</Info>

All org members can read the key status. Returns whether the org has a key
configured and the active policy. The actual key is never returned.

#### Path Parameters

<ParamField path="org_id" type="string" required>
  Organization ID. Must match `X-Organization-Id` (or the API key's org).
</ParamField>

#### Response

<ResponseField name="organization_id" type="string">
  Echo of the path `org_id`.
</ResponseField>

<ResponseField name="has_key" type="boolean">
  `true` when the organization has a stored Anthropic key.
</ResponseField>

<ResponseField name="key_preview" type="string">
  Masked preview of the stored key, or `null` when none is set.
</ResponseField>

<ResponseField name="policy" type="string">
  `"individual"` (org key ignored) or `"enforced"` (org key used first).
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the last update, or `null` when never set.
</ResponseField>

<RequestExample>
```bash cURL (read)
curl -X GET "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "X-Organization-Id: org_abc123"
```

```python Python (read)
import requests

response = requests.get(
    "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key",
    headers={
        "Authorization": "Bearer runtm_xxx",
        "X-Organization-Id": "org_abc123",
    },
)
print(response.json())
```

```javascript JavaScript (read)
const response = await fetch(
  "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key",
  {
    headers: {
      Authorization: "Bearer runtm_xxx",
      "X-Organization-Id": "org_abc123",
    },
  },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200
{
  "organization_id": "org_abc123",
  "has_key": true,
  "key_preview": "sk-ant-***WxYz",
  "policy": "enforced",
  "updated_at": "2026-04-12T18:30:11Z"
}
```
</ResponseExample>

### PUT /api/organizations/{org_id}/anthropic-key

<Info>
  Required scope: `integrations:write`
</Info>

<Warning>
  Org owner or admin role required.
</Warning>

Set the organization Anthropic key, the active policy, or both. To switch a
brand-new org to `enforced`, you must include an `api_key`.

#### Path Parameters

<ParamField path="org_id" type="string" required>
  Organization ID. Must match `X-Organization-Id` (or the API key's org).
</ParamField>

#### Request Body

<ParamField body="api_key" type="string">
  Anthropic API key. Must start with `sk-ant-` or `sk-` when provided.
  Required when switching to `policy="enforced"` for the first time.
</ParamField>

<ParamField body="policy" type="string">
  `"individual"` (default) or `"enforced"`.
</ParamField>

#### Response

Same shape as the GET response, reflecting the updated key and policy.

<RequestExample>
```bash cURL (set)
curl -X PUT "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "X-Organization-Id: org_abc123" \
  -H "Content-Type: application/json" \
  -d '{"api_key": "sk-ant-...", "policy": "enforced"}'
```

```python Python (set)
import requests

response = requests.put(
    "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key",
    headers={
        "Authorization": "Bearer runtm_xxx",
        "X-Organization-Id": "org_abc123",
    },
    json={"api_key": "sk-ant-...", "policy": "enforced"},
)
print(response.json())
```

```javascript JavaScript (set)
const response = await fetch(
  "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key",
  {
    method: "PUT",
    headers: {
      Authorization: "Bearer runtm_xxx",
      "X-Organization-Id": "org_abc123",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ api_key: "sk-ant-...", policy: "enforced" }),
  },
);
console.log(await response.json());
```
</RequestExample>

<ResponseExample>
```json 200
{
  "organization_id": "org_abc123",
  "has_key": true,
  "key_preview": "sk-ant-***WxYz",
  "policy": "enforced",
  "updated_at": "2026-05-09T22:14:00Z"
}
```

```json 400
{
  "detail": "Cannot set 'enforced' policy without an API key. Please provide an API key."
}
```

```json 403
{
  "detail": "Organization context mismatch. Set X-Organization-Id header to match."
}
```
</ResponseExample>

### DELETE /api/organizations/{org_id}/anthropic-key

<Info>
  Required scope: `integrations:write`
</Info>

<Warning>
  Org owner or admin role required.
</Warning>

Remove the organization's Anthropic key and reset the policy to
`"individual"`. Members fall back to their personal keys (or are prompted)
the next time they create a session.

#### Path Parameters

<ParamField path="org_id" type="string" required>
  Organization ID.
</ParamField>

#### Response

Same shape as the GET response, with `has_key: false`, `key_preview: null`,
and `policy: "individual"`.

<RequestExample>
```bash cURL (delete)
curl -X DELETE "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "X-Organization-Id: org_abc123"
```

```python Python (delete)
import requests

response = requests.delete(
    "https://app.runtm.com/api/cloud/organizations/org_abc123/anthropic-key",

        "Authorization": "Bearer runtm_xxx",
        "X-Organization-Id": "org_abc123",
    },

print(response.json())
```

