---
title: "Load Tools"
api: "POST /api/sessions/{session_id}/tools"
description: "Hot-load tools into a running session"
---

Loads tools (knowledge integrations) into a running sandbox. Unlike skills and MCP servers, tools are addressed by provider slug (`notion`, `bigquery`), not directive ID. Providers with no stored credentials are reported under `needs_auth`.

**Required scope:** `sessions:write`

## Path Parameters

<ParamField path="session_id" type="string" required>
  The session ID.
</ParamField>

## Request Body

<ParamField body="provider_slugs" type="string[]" required>
  Provider slugs of the tools to load.
</ParamField>

## Response

<ResponseField name="loaded" type="array">
  `{id, name}` for each tool that loaded.
</ResponseField>

<ResponseField name="needs_auth" type="string[]">
  Providers skipped because no credentials are connected.
</ResponseField>

<ResponseField name="skipped" type="string[]">
  Unknown provider slugs.
</ResponseField>

<RequestExample>
```bash cURL
curl -X POST "https://app.runtm.com/api/cloud/sessions/a6414511-4430-4e1f-8c51-8ea8824dadec/tools" \
  -H "Authorization: Bearer runtm_xxx" \
  -H "X-Organization-Id: org_abc123" \
  -H "Content-Type: application/json" \
  -d '{"provider_slugs": ["notion"]}'
```

```bash CLI
runtm-api session load-tools a6414511-4430-4e1f-8c51-8ea8824dadec notion
```
</RequestExample>

<ResponseExample>
```json 200
{
  "loaded": [{"id": "notion", "name": "Notion"}],
  "needs_auth": [],
  "skipped": []
}
```
</ResponseExample>
