`runtm-api` is a small Go CLI that wraps the Runtime Cloud API. It is intentionally separate from the pip [`runtm` CLI](/open-source/cli/overview) (which handles local sandboxes, scaffolding, and deploys):

| | Pip `runtm` CLI | Go `runtm-api` CLI |
|---|---|---|
| Surface | Local sandbox + deploy | Hosted Cloud API only |
| Audience | Humans + occasional scripts | AI coding agents (Claude Code, Cursor, Codex, ...) |
| Output | Pretty TTY | JSON to stdout, structured errors to stderr |
| Exit codes | Generic | `0` ok / `1` API / `2` auth / `3` usage |
| Distribution | PyPI (`uv tool install runtm`) | Pre-built binary (`curl ... \| bash`) |

Most humans use both: the pip CLI for day-to-day work, the Go CLI when an agent needs to act on the hosted platform programmatically.

## Install

```bash
curl -fsSL https://runtm.com/install | bash
```

This downloads a pre-built binary for your platform (macOS / Linux × amd64 / arm64), verifies its SHA-256 checksum, and installs `runtm-api` to `/usr/local/bin`. If Claude Code or Cursor is detected, the bundled agent skill files are auto-installed too.

```bash
export RUNTM_API_KEY=runtm_sk_live_...   # from app.runtm.com → Settings → API Keys
runtm-api auth status
```

### Install a specific version

```bash
curl -fsSL https://runtm.com/install | RUNTM_VERSION=0.1.0 bash
```

### Install into a directory you own (no sudo prompt)

```bash
curl -fsSL https://runtm.com/install | RUNTM_INSTALL_DIR="$HOME/.local/bin" bash
```

### Installer environment variables

| Variable | Default | Purpose |
|---|---|---|
| `RUNTM_VERSION` | `latest` | Version to install. Accepts `latest`, `0.0.1`, `v0.0.1`, or `packages/agent/v0.0.1`. |
| `RUNTM_INSTALL_DIR` | `/usr/local/bin` | Where the binary lands. |
| `RUNTM_REPO` | `runtm-ai/runtm` | Source repository (override for forks / mirrors). |
| `RUNTM_SKIP_SKILLS` | unset | Set to `1` to skip the post-install skill install. |

### Install via `go install` (Go developers)

If you already have Go 1.23+ and prefer to compile from source:

```bash
go install github.com/runtm-ai/runtm/packages/agent/cmd/runtm-api@latest
runtm-api skills install
```

## Auth and config

| Setting | Env var | Fallback |
|---|---|---|
| API key | `RUNTM_API_KEY` | `~/.runtm/credentials` (written by `runtm login` in the pip CLI) |
| API URL | `RUNTM_API_URL` | `~/.runtm/config.yaml`, then `https://app.runtm.com/api/cloud` |
| Org ID | `RUNTM_ORG_ID` | `--org` flag; auto-resolved when the key is org-scoped |

The same API key works for both this CLI and the pip CLI.

## Commands

| Command | What it does |
|---|---|
| `runtm-api auth status` | Verify the API key against `/api/v1/me`. |
| `runtm-api session create` | Create a sandbox (no prompt). |
| `runtm-api session launch` | Create + fire a prompt as a background task. |
| `runtm-api session list` | List sessions for the API key. |
| `runtm-api session status <id>` | Get state + `last_prompt` polling fields. |
| `runtm-api session prompt <id> <text>` | Stream a prompt as SSE → JSON lines. |
| `runtm-api session search -q <text>` | Fuzzy-search sessions with filters. |
| `runtm-api session exec <id> -- <cmd>` | Run one command in the sandbox. Add `--json` for `{stdout, stderr, exit_code}`. |
| `runtm-api session connect <id>` | Attach an interactive PTY (needs a TTY on stdin). |
| `runtm-api session grade <id>` | The run's evaluation verdict. |
| `runtm-api session approvals list\|resolve` | See and clear a stalled run's approval gates. |
| `runtm-api session load-skills\|load-mcps\|load-tools <id> ...` | Hot-load capabilities into a running sandbox. |
| `runtm-api session file upload\|download <id> ...` | Binary-safe file transfer in and out of the sandbox. |
| `runtm-api session destroy <id>` | Tear down a sandbox. |
| `runtm-api session git <id> <op>` | Run a git operation (commit, push, create_branch_and_pr, ...). |
| `runtm-api agents list\|create\|update\|delete` | The agent roster (no `--type`); triggers with `--type slack\|github\|linear\|email`. |
| `runtm-api agents scorecard` | Per-agent performance, spend, and budget. |
| `runtm-api template list` | List org templates (requires `--org` / `RUNTM_ORG_ID`). |
| `runtm-api template get <id>` | Inspect one template, including its attached skills and build staleness. |
| `runtm-api template context get\|set\|resolve <id>` | The template's instruction block and the effective stack. |
| `runtm-api template guardrails list\|create\|update\|delete\|resolve <id>` | Template-scoped guardrails. |
| `runtm-api guardrails rules\|hooks\|network ...` | Org guardrail content: allowlist rules, hooks, egress rules. |
| `runtm-api skills list --template <id>` | Skills a session from that template loads. |
| `runtm-api skills import\|discover\|resync\|lock\|unlock` | Skill lifecycle at org scale. |
| `runtm-api scheduled-agents list` | Cron-driven agents, with `next_run_at`. |
| `runtm-api scheduled-agents run-now <id>` | Fire one run immediately (works on disabled agents). |
| `runtm-api groups usage <team_id>` | What an owning group owns. |
| `runtm-api github installations\|repos\|add-repo` | GitHub App installations and repo access. |
| `runtm-api deployments list\|get\|logs\|destroy` | The deployments sessions ship (alias: `deploy`). |
| `runtm-api skills install` | Install the agent skill files into `~/.claude/skills/runtm/` and/or `~/.cursor/skills/runtm/`. |

Run `runtm-api --help` or `runtm-api <command> --help` for full flag reference.

### Running commands in a sandbox

`session exec` prints the raw PTY stream by default, which merges stderr into stdout and carries the sandbox shell's startup banners. Pass `--json` whenever the output will be parsed:

```bash
runtm-api session exec <id> --json -- npm test
# {"stdout": "...", "stderr": "...", "exit_code": 1}
```

The two streams are captured separately and PTY carriage returns are stripped. The process still exits with the remote exit code, so under `set -e` capture the output with `|| true` and read `exit_code` instead.

Bash history expansion is disabled for the command in both modes, so a literal `!` in a heredoc, commit message, or regex reaches the sandbox intact. A paused sandbox is resumed automatically by `exec`, `connect`, and the file commands.

## Output and exit codes

- Stdout is always JSON. For `session prompt`, stdout is JSON lines (one per SSE event).
- Stderr carries structured error JSON: `{"error": "...", "status": 401, "hint": "..."}`.
- Exit codes:

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | API error (4xx / 5xx response) |
| `2` | Auth error (missing or invalid key) |
| `3` | Usage error (bad flags) |

## Agent skills

The CLI ships with a set of SKILL.md files **embedded into the binary** ([`packages/agent/skills/`](https://github.com/runtm-ai/runtm/tree/main/packages/agent/skills)):

- `SKILL.md`: command cheat sheet, auth, error recovery, trigger words (`runtm`, `runtime`).
- `runtm-sessions.md`: multi-step workflows (launch from template, iterate, poll, open PR).
- `runtm-templates.md`: discovering, inspecting, and verifying org templates.
- `runtm-automation.md`: scheduled agents: cron syntax, `run-now`, debugging a schedule that didn't fire.
- `runtm-integrations.md`: skills, MCP servers, tools, and how attachments reach a template.
- `runtm-agents.md`: Slack/GitHub event-driven agents.
- `runtm-debug.md`: inspecting a session when something is wrong.

These are workflow recipes that teach the agent how to use the CLI. They are auto-installed by the one-liner installer when `~/.claude` or `~/.cursor` exists, and can be re-installed any time with:

```bash
runtm-api skills install
```

## Source

The CLI lives at [`packages/agent/`](https://github.com/runtm-ai/runtm/tree/main/packages/agent) in the open-source `runtm-ai/runtm` repository. Releases are cut by pushing a `packages/agent/vX.Y.Z` tag, which triggers a GitHub Actions workflow that publishes pre-built binaries to GitHub Releases.
