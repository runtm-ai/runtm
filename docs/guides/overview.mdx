The Documentation tab teaches the method: six steps, capable first, then safe. This tab is where you copy a working agent. Each example below is one agent for a payments operations team, built in the same six steps, with the concrete values filled in: the job, the evaluation categories, the tools and their credential scopes, the runbook skill, the trigger, the seeded cases, and the guardrails added last.

Every page reads at its `.md` URL as a runbook for the `runtm-api` CLI, because each dashboard step carries its CLI equivalent as a hidden comment.

## Payments operations

<CardGroup cols={3}>
  <Card title="Payment support agent" icon="headset" href="/guides/payments/support-agent">
    Reconstructs a charge, decline or refund from Zendesk, Stripe and the ledger and drafts a cited reply. Slack mention and email inbox. Approval before anything reaches the customer.
  </Card>
  <Card title="Fraud and risk review agent" icon="shield" href="/guides/payments/fraud-risk-agent">
    Every 30 minutes, turns new Radar reviews and velocity alerts into a review packet posted to Slack. Enforcement stays human.
  </Card>
  <Card title="Merchant underwriting agent" icon="building-columns" href="/guides/payments/underwriting-agent">
    Compares KYB results, registry data and the application, and writes a decision memo with open items. Linear tickets and a weekly periodic review.
  </Card>
  <Card title="Multi-agent: underwriting re-review" icon="sitemap" href="/guides/payments/multi-agent-underwriting">
    An Underwriting Agent triggered from Slack delegates research to a Risk Agent and a block to an Engineering Agent, each behind a human approval. How subagents are triggered, attributed and graded.
  </Card>
</CardGroup>

The three single-agent examples follow the same order as [Build an agent](/build/overview); the multi-agent example builds each agent that way and then wires them together. If you are building something else, pick the closest one and change the values.

| | Support | Fraud and risk | Underwriting |
|---|---|---|---|
| Reached by | Slack mention, email | cron every 30 minutes, Slack post | Linear assignment, weekly cron |
| Tools | Zendesk, Stripe, Postgres | Stripe, BigQuery, Postgres | Middesk (custom), Postgres, Notion |
| Agent-scoped credential | Zendesk bot token | Stripe key with Radar read | Middesk key |
| Success categories | decline-explanation, duplicate-charge, refund-status | card-testing, velocity-spike, merchant-linkage | new-application, periodic-review, discrepancy |
| Approval gate | before posting a reply | before recommending a block | before attaching the memo, before a document request |
