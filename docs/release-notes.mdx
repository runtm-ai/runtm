Every entry below is live in production. The date is when it became available, in Pacific Time. Setup notes say what an admin needs to do before people can use it.

<Update label="Oct 9, 2026" tags={["Slack", "Integrations"]}>
  ## Agents share files and images in Slack

  Agents started from Slack can post a screenshot, document or export straight into their own thread.

  ![A Runtime agent posting screenshots into its Slack thread](/images/release-notes/slack-file-sharing.png)

  **Setup:** turn on **Share files and images** for the agent. It's off by default. Slack apps installed earlier may need a reinstall to grant `files:write`. Uploads are limited to 20 MB.
</Update>

<Update label="Oct 8, 2026" tags={["Slack", "Triggers"]}>
  ## Start an agent with an emoji reaction

  React to a Slack message with an emoji you've configured, and the agent picks up that message and its files and replies in the same thread. Each message and emoji starts one run.

  **Setup:** add an emoji trigger rule in the agent's Slack settings. You can limit it to certain channels and user groups. The bot must be able to read the channel. [Learn more](/build/how-it-works/triggers)
</Update>

<Update label="Oct 6, 2026" tags={["User Experience"]}>
  ## A new dashboard, with Ask Runtime anywhere

  A redesigned dashboard in light and dark mode, with clearer navigation for sessions and settings. Press <kbd>⌘K</kbd> or <kbd>Ctrl K</kbd> on any signed-in page to open Ask Runtime. Use it to ask about the platform, set things up or pick an agent.

  ![The new Runtime dashboard home with Ask Runtime](/images/release-notes/dashboard-ask-runtime.png)
</Update>

<Update label="Oct 5, 2026" tags={["Microsoft 365", "Integrations"]}>
  ## Runtime agents in Microsoft Teams and Microsoft 365

  Each agent can have its own Teams bot. It answers @mentions and DMs, works in threads and asks for approval right in the conversation. The Microsoft 365 connector covers mail and calendar, Teams, Excel, SharePoint, OneDrive, OneNote and To Do. On October 9 we added managed bot setup, access to selected SharePoint sites and a shared mailbox for each agent.

  ![The Connect Microsoft Teams dialog, naming a new Teams agent](/images/release-notes/teams-create-bot.png)

  **Setup:** an organization admin enables Teams and completes Microsoft admin consent, then creates the agent's bot and scopes what it can reach. A delegated connection uses the access of the account that connected it. The per-agent identity options use the agent's own scoped access.
</Update>

<Update label="Sep 24, 2026" tags={["Triggers", "API"]}>
  ## Start an agent from events in your systems

  Give each agent several named webhook triggers, verified by URL token, header token or HMAC-SHA256. They accept JSON and Salesforce-style SOAP/XML notifications. An optional `Idempotency-Key` drops repeat deliveries for 24 hours.

  **Setup:** create the trigger, then give the sending system its URL and verification secret. Set the instructions, rate limit and where results should go. [Learn more](/build/how-it-works/triggers)
</Update>

<Update label="Sep 18, 2026" tags={["Slack", "Governance"]}>
  ## Approvals and questions in the Slack thread

  An agent can end its turn with a question or an approval request. Runtime pauses the run, shows **Approve** and **Reject** in the Slack thread that started it, checks the approver's role on the server and resumes the same agent with the answer.

  **Setup:** the agent's runbook has to request approval at the step that needs it. Choose who can approve. Approval requests expire. [Learn more](/guides/recipes/request-approval-from-a-run)
</Update>

<Update label="Sep 16, 2026" tags={["Agents", "User Experience"]}>
  ## A guided path to your first working agent

  New agents now come with a setup guide that shows what's built, which connections are missing and the next step. A channel step counts as done only after the agent finishes a real run in that channel.

  ![The setup guide for a new agent in Quickstart](/images/release-notes/guided-first-agent.png)

  **Setup:** start from the new-agent flow. Some knowledge connections still need approval from the provider's admin. [Learn more](/build/overview)
</Update>

<Update label="Aug 20, 2026" tags={["Sessions", "Collaboration & Sharing"]}>
  ## Share a live preview with someone outside your organization

  Invite a specific email address to one preview port, and revoke access when you're done. You can do this from the dashboard, the API or the CLI. When an invited reviewer opens a paused preview, it wakes up.

  **Setup:** the person you invite has to sign in to open the preview. Sharing from the CLI needs v0.0.16 or later. [Learn more](/cloud-api/sessions/preview-shares-create)
</Update>

<Update label="Jul 29, 2026" tags={["CLI"]}>
  ## Manage agents, guardrails and schedules from the CLI

  `runtm-api` v0.0.14 covers the agent roster, evaluator criteria, scorecards and run grades, plus template guardrails and context. For scheduled agents you can create one disabled, use `run-now` to test it, then enable it.

  **Setup:** use `runtm-api` v0.0.14 or later with an org key that has the right scopes. [Learn more](/cloud-api/agent-cli)
</Update>
