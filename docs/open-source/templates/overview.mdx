Templates are optional starting points. Your agent can start from scratch or use a template to get going faster.

## Available templates

<CardGroup cols={2}>
  <Card title="backend-service" icon="server" href="/templates/backend-service">

  </Card>
  <Card title="static-site" icon="file-code" href="/templates/static-site">
    Next.js static export for landing pages and docs.
  </Card>
  <Card title="web-app" icon="browser" href="/templates/web-app">
    Fullstack app with Next.js frontend and FastAPI backend.
  </Card>
  <Card title="docker" icon="docker">
    Bring your own Dockerfile for Go, Rust, Elixir, or any language.
  </Card>
</CardGroup>

## When to use templates

| Building | Template |
|----------|----------|
| REST API, webhook handler, agent backend | `backend-service` |
| Landing page, documentation, marketing site | `static-site` |
| Dashboard, SaaS app, admin panel | `web-app` |
| Go, Rust, Elixir, or custom runtime | `docker` |

<Tip>
Your agent can also start from scratch - templates are just a faster starting point. The `docker` template is ideal when you want to bring your own Dockerfile without any scaffolding.
</Tip>

## Getting started

```bash
runtm init backend-service
cd backend-service
runtm deploy
```

Every template deploys without edits. Add your code, then redeploy.

## What's included

```
my-project/
├── runtm.yaml              # Deployment manifest
├── Dockerfile              # Build configuration
├── README.md               # Documentation
├── AGENT.md                # AI assistant instructions
└── [application code]
```

## Optional features

Enable features in your `runtm.yaml`:

```yaml
features:
  database: true   # SQLite with persistent storage
  auth: true       # Better Auth (web-app only)
```

<Note>
Auth requires database to be enabled. Only available on `web-app` template.
</Note>

## Template requirements

| Template | Min tier | Port | Runtime |
|----------|----------|------|---------|
| `backend-service` | starter | 8080 | `python` |
| `static-site` | starter | 3000 | `node` |
| `web-app` | starter | 3000 | `fullstack` |
| `docker` | starter | your choice | not required |

Use `performance` or `pro` for web apps that need more CPU or memory.

<Note>
The `docker` template doesn't require a `runtime` field in `runtm.yaml` since you provide your own Dockerfile.
</Note>
